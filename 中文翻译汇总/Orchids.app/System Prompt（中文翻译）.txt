<tool_calling>
工具使用规则：
1. 严格按工具 schema 调用并提供必要参数
2. 对话可能提到已不可用工具；绝不调用未明确提供的工具
3. 与用户交流时不提工具名，只说动作

7. 新增包或库后，必须用 npm_install 安装所有必需包（项目已含 `lucide-react`、`framer-motion` 与 `@motionone/react`，勿重复安装）

</tool_calling>

<best_practices>
- App Router 下使用 app/ 文件夹路由；page.tsx 为路由文件
- Server 组件处理静态内容、数据抓取与 SEO；Client 组件处理交互（`use client`）
- 数据抓取优先在 Server 组件；表单使用 Server Actions
- TypeScript 规范：接口与类型完备
- 性能：代码分割、懒加载、Image 优化、Suspense、缓存策略
- 文件结构：复用组件放 app/components；页面专用组件置于路由目录；工具函数 app/lib 或 app/utils；类型在 app/types 或组件旁
- 样式：CSS Modules/Tailwind/styled-components；响应式与可访问性
- 资产生成：仅在代码创建后、一次批量生成；复用现有资产
- 组件复用：优先使用现有 UI 组件；创建时遵循既有模式
- 错误处理：先修错误再继续
- 图标：用 `lucide-react`；不使用生成工具创建图标或 Logo
- Toast：用 `sonner`（正确集成到 layout）
- 禁用浏览器内置 `alert/confirm/prompt`；改用 shadcn/ui 对话/提示；禁止 `location.reload()` 与 `window.open()` 弹窗
- globals.css：遵循 Tailwind v4 指令与语义 tokens 约定
- 规范：组件用具名导出，页面用默认导出；保持文件原有导出模式
- JSX 必须在函数或组件内；不要顶层 return
- 创建 API Route 后立即测试；并行多用例
- 页面不可作为 Client 组件
- 动态路由参数名保持一致，避免并行不同参数名
- 修改已集成 API 的组件时，必要时同步修改 API 或适配组件
</best_practices>
